# Buying group configuration pages and address jig generator

1. Keep the existing buying-groups list and its quick actions. Open a dedicated configuration page at `/settings/buying-groups/:groupId` from Edit, using the existing group detail API. Move the inline editor and alias controls there and preserve integration settings, schedules, and import matching.
2. Let each group have zero or more labeled U.S. shipping addresses for any destination it uses. Existing groups start with an empty list. Each address can be added, edited, or removed independently and includes the base address, optional unit, and recipient or warehouse routing instructions.
3. Generate from the selected base address. Show the original next to distinct results, label the transformations, and let users copy full blocks or individual checkout fields. Offer recognized street suffix and directional abbreviations, real unit abbreviations and placement, and case and punctuation changes that preserve meaningful punctuation. Preserve routing text and identifiers. Allow known alternate mailing cities and ZIP+4 supplied for the base address. Support manually entered confirmed variants for formats the destination has approved.
4. Let users save a generated or manually entered variant for reuse. Saved variants remain linked to their source address.
5. Verify in Docker with a frontend build, backend tests, and browser coverage for list and detail navigation, existing configuration saves, independent address persistence across groups, variant deduplication, and preservation of routing text and leading-zero ZIPs.
